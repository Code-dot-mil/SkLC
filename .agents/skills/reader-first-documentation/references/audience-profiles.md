# Reusable audience profiles

Read existing project documentation and source before interviewing. Reuse accepted profiles instead of collecting the same information for every document. A profile describes task-relevant knowledge, not invented demographics or marketing archetypes.

When needed, collect the missing information in one intake:

- Who arrives first, what are they trying to accomplish, and what other readers matter?
- What can they already do, and which project concepts are unfamiliar?
- Which questions must the docs answer, and what demonstrates success?
- Which product intentions or constraints cannot be established from source?

Record each audience with its goal, assumed knowledge, unfamiliar concepts, key questions, and observable successful outcome. Include entry points or reading paths when known. Mark inferred details as provisional and distinguish them from user-confirmed decisions. Preserve that provenance until the user confirms or corrects it.

Keep writing-process rules in the skill. The project's audience file should describe its readers and help select content, not accumulate generic editorial commandments.

Update profiles when new evidence or accepted decisions change the audience. For an isolated small edit, use existing context without creating a profile file merely to satisfy this workflow.
